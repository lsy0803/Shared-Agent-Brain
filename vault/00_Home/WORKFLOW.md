# 多 Agent 协作工作流

## 直接维护

用户准许的 Agent 可读取、写入、贡献和维护其负责的任务。各项目的实际负责者直接保存需求、状态和结果，不需要固定经某个 Agent 合并。初始作者不永久占有文件。

新项目按使用者自己的工作区规范建立；这里不强制编号或工具。共享画像与经验是跨 Agent 的知识，不属于某个模型。

## 按需读取

| 任务 | 应取上下文 |
| --- | --- |
| 普通问答、独立小改 | 问题、目标文件、适用规则 |
| 项目续接 | 当前状态、实际产物、下一步 |
| 个性化规划 | 相关画像与主题正文 |
| 技术选型或疑似旧问题 | 检索相关经验，再读命中原文 |
| 改已有笔记 | 当前目标正文、必要来源和版本 |

首次使用、规则变化或上下文丢失时补读适用规则；稳定且未变的已读内容可以复用。摘要只用于定位，依赖某条结论时回到原件。不要为了“完整”读取不相关的项目或隐私。

## 修改别人写过的内容

- 有来源的新信息、明显笔误和失效路径，可以直接做最小修改。
- 用户更正、一手证据或复现结果证明旧结论有误，可以修订当前结论，并简记修改者、依据、变更和适用范围。
- 只有不同偏好或证据未决时，保留原有效内容，记录争议，必要时使用 [争议模板](../90_Templates/DISPUTE.md)。
- 删除整篇文件、批量清理或不可恢复覆盖，按用户明确范围处理；不明时先确认。
- 旧结论已被替代时，不把旧对话、旧摘要或旧分支直接写回当前事实。

## 最小溯源

重要更新保存 Agent、日期、来源与范围；区分用户自述、已核事实、推断、假设、争议和未知。无需给每句文字填标签，也无需为每个小改动创建提案。

重要纠错可用 [纠错模板](../90_Templates/CORRECTION.md)，也可在原笔记末尾写一行来源说明。

## 同时写入

不同文件可以分工维护。同一文件同时只安排一个写入者；写前检查当前内容，版本变化后先比较。必要时使用独立草稿、Git 分支或宿主提供的锁。

SHA-256 是版本指纹，不是原子锁。没有真实同步/锁机制时，不承诺同文件并发零覆盖。也不因写入成功就声称其他会话已经读取。

## 争议

先由了解该项目的协作者核证据。若需要独立复核，选择未参与争议的获准 Agent；重要且无法客观判定的用户取舍交用户决定。

提案被拒后，可凭新证据或明确规则错误上诉一次。失败后关闭；决定性新证据或重大误判可申请一次用户确认的重开。日常修改无需走这一流程。

## 信息共享

正常任务访问与公开发布分别处理。按 [记录规则](RECORDING.md) 处理敏感事实。公开、整库上传或交给新的服务，需要用户明确对应范围；不默认同步整个 Vault。

本模板不实现自动检索、自动记忆、云端同步、权限控制或文件锁。可先用目录、链接和关键词检索，真实出现瓶颈后再增加工具。
